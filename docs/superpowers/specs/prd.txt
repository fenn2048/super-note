产品功能需求文档 (PRD) - super-note 音视频媒体库扩展
一、 文档概述
1.1 项目背景
super-note 是一款自建的、集笔记与社交（说说）于一体的个人知识管理系统。为了丰富系统的内容承载能力，现计划在系统内新增一个“音视频媒体库”大模块，支持大批量（2TB+）的高清影视资源与 MP3 音乐资源的统一管理、深度交互（影/乐评打点跳转）以及全站跨模块（说说、笔记）联动。

1.2 核心设计约束
硬件限制：部署服务器为 4核4G，剩余硬盘空间仅约 20GB。

带宽限制：腾讯云服务器公网带宽有限，无法承载大流量的高清视频流高并发分发。

版权与安全：2TB 影视资源多为受版权保护内容，必须规避公共云盘官方的算法和谐，且需严格限制仅网站登录用户可看（防盗链）。

1.3 核心技术落地架构
存储与分发（302 重定向）：2TB 资源托管在阿里云盘/夸克网盘，服务器本地部署 Docker 化的 Alist 容器进行挂载。用户播放时，后端鉴权通过后通过内网调用 Alist API 获取网盘临时直链，前端通过 302 重定向直接向网盘 CDN 请求数据。服务器带宽流量开销为 0。

网络隔离：Alist 容器关闭公网端口映射，仅允许 super-note 业务容器在 Docker 内网（Default Bridge）与其通信，彻底杜绝直链被外部抓取的可能。

三、 功能需求矩阵 (Functional Requirements)
1. 媒体库基础管理模块
1.1 媒体合集（专辑）管理
功能描述：支持用户创建、修改、删除和查询视频合集（如电影系列、教程合集）或音乐合集（歌单）。

数据字段：合集 ID、标题、类型（视频/音乐）、封面图（支持外链）、合集简介。

合集推荐理由：用户在收藏或推荐该合集整体时，可以撰写并编辑一段简短的导语（作为合集的全局推荐语）。

1.2 媒体单品（单部视频/单曲）管理
功能描述：合集内部具体音视频内容的列表展示与增删改查。

视频单品字段：视频名称、视频封面、视频简介、Alist 相对路径。

音乐单品字段：歌曲名称、歌手、时长、单曲封面、Alist 相对路径。

2. 深度互动与评论模块
2.1 用户推荐理由（单品级）
功能描述：用户可以针对合集内的某一个特定视频或某首单曲，撰写自己独立的推荐理由。

交互规则：支持已登录用户创建和二次编辑。前端以卡片或瀑布流形式展示该单品的“总推荐用户数”以及“各用户的具体推荐文本”。

2.2 深度影评/乐评系统（长文大模块）
功能描述：独立于普通评论的高级长文模块，支持图文混排。

时间戳打点创建（方案A）：在编写影/乐评时，页面必须保持媒体播放器可见。富文本工具栏提供【插入当前时间】按钮，点击后系统自动捕获播放器当前的秒数（如 755 秒），并在光标处自动转化为标准的 Markdown 锚点：[12:35](#t=755)。

时间戳超链接跳转：影评发布后，用户在阅读时，点击文本中的 12:35 数字超链接，页面不刷新，页面上的视频播放器（DPlayer）或底部的全局音乐播放器（APlayer）立即无缝跳转到 12分35秒 处并自动播放。

2.3 常规评论流（短评/吐槽）
功能描述：视频或单曲下方的普通短评流（字数受限，针对单品本身）。

时间戳支持：短评同样支持时间戳跳转功能。用户手动输入 12:35 格式，前端渲染时通过正则表达式 ^(\d{2}):(\d{2})$ 自动将其包装为可点击的播放器控制跳转标签。

3. 播放器全局交互体验（UI/UX）
3.1 视频播放器 (DPlayer)
展现形式：固定嵌于视频详情页的核心区域。

核心特性：高清流畅播放，原生支持 HTTP Range 精准 seek() 控制。

3.2 音乐播放器 (APlayer) —— 全局常驻悬浮
展现形式：常驻在页面的底部或侧边（吸底悬浮状态）。

全局行为：用户点击播放歌曲后，即使在左侧导航栏切换到笔记模块、说说模块或个人中心，音乐绝不断开，保持无缝后台播放。

控制模式：原生支持单曲循环、列表循环、随机播放、顺序播放四种模式。

4. 跨模块组件化联动需求（v1.1.0 增补）
4.1 媒体库 ──> 说说模块（动态分享）
分享交互：在媒体合集详情页及单品播放页提供【分享到说说】按钮。点击后唤起说说发布框，并将该媒体资源序列化为一个特殊的“快捷卡片”附加在说说编辑框下方。

说说墙卡片渲染：说说发布后，动态流中会自动渲染对应的媒体卡片（展示封面、标题、类型、包含单品数）。

原地播放交互：若分享的是音乐单品，用户在浏览说说墙时，点击卡片上的【播放】按钮，常驻在页面底部的全局 APlayer 播放器直接接管并开始播放该歌曲，无需跳转离开说说模块。

4.2 媒体库 ──> 笔记模块（文内插入）
编辑时插入：在 super-note 所有笔记模块的编辑器工具栏中，新增【插入媒体】按钮。点击弹出微型媒体选择器，选中后自动在 Markdown 光标处插入特定短代码（如 [media type="video" id="v_10086"]）。

阅读时渲染：笔记进入阅读/预览模式时，前端解析器将短代码自动转化为内嵌的优雅媒体卡片。

插入视频：卡片内部直接嵌入微型 DPlayer，用户可在阅读笔记的同时，在笔记内部直接点击播放、拖拽进度，并响应时间戳跳转。

插入音乐：点击后将歌曲直接唤醒并推送到页面底部的全局 APlayer 播放列表中。

四、 数据库核心表结构设计 (Schema)
1. 媒体资源表 (Media_Item)
JSON
{
  "id": "String (UUID)",
  "title": "String (视频名/歌名)",
  "type": "String (video / audio)",
  "cover_url": "String (外链海报地址)",
  "alist_path": "String (例如 /夸克网盘/Movies/Inception.mp4)",
  "artist": "String (歌手，仅audio有效)",
  "duration": "Integer (秒数)"
}
2. 深度影评/评论表 (Media_Review)
JSON
{
  "id": "String (UUID)",
  "media_id": "String (关联Media_Item)",
  "user_id": "String (关联用户)",
  "type": "String (long_review影评长文 / short_comment短评)",
  "title": "String (可为空)",
  "content": "Text (保存带有时间戳标记的文本)",
  "created_at": "Timestamp"
}
3. 说说/笔记关联附件结构 (Attachment_Schema)
在原有的 Shuoshuo 和 Notes 表结构中，新增可选的 attachment 字段：

JSON
{
  "attachment": {
    "target_type": "media_collection / media_item", 
    "media_type": "video / audio",
    "target_id": "String (关联对应媒体表ID)" 
  }
}
五、 性能调优与安全控制规范
直链本地内存缓存：网盘直链有过期时间且高频请求易被官方限流。后端在获取直链后，必须将其在服务器本地（如使用 Node 内存缓存或 Redis）缓存 45 分钟。缓存期内用户反复切换或多用户访问同一视频，直接从缓存返回，严禁频繁请求 Alist。

网盘防盗链（Referer 限制）：在 Alist 后端或 super-note 统一网关中配置严格的 Allowed-Origins 策略，只有当请求头的 Referer 来自你的自建网站域名时才允许下发资源，防止 2TB 影视直链被恶意公开。

前端组件复用 (MediaCard)：前端需要将说说模块、笔记模块、媒体模块中的“卡片展示形式”封装为同一个标准的 <MediaCard /> UI 组件，输入相同的 target_id 即可在三处获得完全一致的高清无缝播放和跳转体验，节约服务器空闲的 20G 空间中的前端打包体积。
